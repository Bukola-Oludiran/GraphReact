# M6.6 — TS feature parity audit, per-engine sign-off

**Status:** living document. Last updated: 2026-05-02 (M12.3b-phase2 — `xtask webkit-clone` + `xtask webkit-build` orchestration scaffolded for Linux/Windows vendoring track; macOS continues using the system framework + the M12.3b-phase1.5 extern-C symbol shim for `JSC::VM::drainMicrotasks`).

The M6.6 audit (originally recorded in `~/.claude/plans/toasty-crafting-lantern.md`, which is lost on disk; the equivalent reconstruction at `~/.claude/plans/graphreact-rust-later-milestones.md` carries the M6.6 substrate forward as the engine-parity column for M17 Go) verified that the Rust **runtime** (graphreact-core + graphreact-algorithms) supports every feature the TS reference does. This document tracks the **second axis**: for each JS-facing hook / API surface, is the **engine bridge** (NAPI vs JSC) wired through?

The runtime is the same across engines. The audit at the runtime level was signed off as part of M6.6 (NAPI work). Per-engine sign-off for JSC tracks how much of the runtime is reachable from JS code running on the JSC engine vs the NAPI embed path.
