# M-Ingress wire-format spec — endpoint catalog

**Status:** SHIPPED 2026-05-09 (Phases 1 + 2 + 3). This is the protocol-level reference; the milestone narrative + decision rationale live in [m16.5-ingress.md](m16.5-ingress.md). Companion ecosystems (visualizer hooks, CLI clients, third-party integrations) pin against this document.

## Endpoint summary

| Method | Path | Purpose | Phase |
|---|---|---|---|
| `POST` | `/v1/nodes/:id/messages` | Single-message inject | 1 |
| `POST` | `/v1/nodes/:id/call` | Synchronous request/response | 2 |
| `POST` | `/v1/nodes/:id/messages/bulk` | Streaming NDJSON inject | 3 |

All endpoints share the `/v1/` versioned prefix. Companion ecosystems pin against this version; breaking schema changes will land at `/v2/` with `/v1/` preserved for one transition window per the M16-Backend P4 management API contract.

## Authentication

All ingress endpoints sit behind the same bearer-token middleware as the rest of the management API. When the daemon is started with `--observer-token-env <var>` (or `--observer-token-file <path>`), every request must carry `Authorization: Bearer <token>`. Bare loopback binds without `--observer-token-*` skip auth (development convenience).

| Status | Body | Meaning |
|---|---|---|
| `401 Unauthorized` | `401 unauthorized` | Missing or wrong bearer. `WWW-Authenticate: Bearer realm="graphreact-observer"` set on response. |

## CORS

Baseline CORS layer (Phase 1) at the management-API router level:

- `Access-Control-Allow-Origin: *`
- `Access-Control-Allow-Methods: GET, POST, OPTIONS`
- `Access-Control-Allow-Headers: authorization, content-type, idempotency-key`

Suitable for loopback bind defaults; production deploys behind a header-injecting reverse proxy provide their own per-origin policy. M-Prod refines (per-origin allowlists, credential modes).

## Manifest annotation

Component author opts in to ingress acceptance per-shape inside the manifest object their component returns:

```javascript
function Aggregator() {
  const emit = useEmit();
  useMessage('query', (msg) => {
    emit('query_result', { answer: 42 });
  });
  return {
    accepts: ['reading'],                                // node-to-node delivery
    emits: ['rollup', 'query_result'],
    accepts_external: ['calibrate'],                     // POST /messages + POST /messages/bulk
    accepts_external_call: [                             // POST /call
      { request_type: 'query', reply_type: 'query_result' },
    ],
  };
}
```

**Default-deny semantics:** absent or empty means the node refuses every external type for that shape. The two acceptance lists are independent — declaring `accepts_external` does NOT grant call-shape acceptance and vice versa. Nodes that want both must declare both. Same shape exposed to Python bodies via `dict` returns.

## POST /v1/nodes/:id/messages — single-message inject

Single-shot fire-and-forget HTTP injection. Phase 1 contract: 202 = queued; manifest gating happens at delivery and surfaces in the telemetry stream (`MessageDelivered { accepted: false }`).

### Request

```http
POST /v1/nodes/sensor.temp.1/messages HTTP/1.1
Authorization: Bearer <token>
Content-Type: application/json
Idempotency-Key: 7b3f8a2e-9c1d-4f8b-a3e5-2b8a1f3c6d7e

{ "type": "calibrate", "payload": { "offset": 0.5 } }
```

| Header | Required | Notes |
|---|---|---|
| `Authorization: Bearer <token>` | iff token configured | See Authentication. |
| `Content-Type: application/json` | yes | Body is the inject envelope. |
| `Idempotency-Key: <opaque-string>` | no | Optional. Same-key replay within 10 min returns 409 without crossing the bridge. Cache cap 10 000 entries; LRU-half eviction at cap. |

| Body field | Required | Notes |
|---|---|---|
| `type` | yes | Message type, runtime-checked against `manifest.accepts_external`. |
| `payload` | no (default `null`) | Arbitrary JSON forwarded verbatim to the node's inbox. |

### Responses

| Status | Body | Meaning |
|---|---|---|
| `202 Accepted` | `{ "status": "accepted" }` | Message queued onto node's inbox. **Manifest enforcement happens at delivery**, NOT here — rejection surfaces in `MessageDelivered { accepted: false }` events on the live stream. |
| `400 Bad Request` | (axum default) | Malformed body / missing `type` field. |
| `401 Unauthorized` | `401 unauthorized` | Bad bearer. |
| `404 Not Found` | `{ "error": "node_not_found" }` | Node id did not resolve. |
| `409 Conflict` | `{ "error": "idempotency_conflict", "key": "..." }` | `Idempotency-Key` matched a non-expired entry. |
| `503 Service Unavailable` | `scheduler bridge closed` / `scheduler bridge dropped response` | mpsc bridge full or scheduler shut down. |

## POST /v1/nodes/:id/call — synchronous request/response

Request/response with auto-correlated reply matching. The runtime captures inbound `correlation_id` per-handler-invocation and auto-tags the FIRST outgoing emit whose `type` matches the call's declared `reply_type`. The `PendingCalls` registry resolves the awaiting `tokio::sync::oneshot::Sender<Value>` immediately at emit-time (independent of actual graph delivery).

### Request

```http
POST /v1/nodes/aggregator.zone-a/call HTTP/1.1
Authorization: Bearer <token>
Content-Type: application/json

{ "type": "query", "reply_type": "query_result", "payload": {"q": 1}, "timeout_ms": 30000 }
```

| Body field | Required | Default | Notes |
|---|---|---|---|
| `type` | yes | — | Inbound message type. Runtime-checked against `manifest.accepts_external_call[*].request_type`. |
| `reply_type` | yes | — | Expected reply type. Runtime-checked against the matching entry's `reply_type`. |
| `payload` | no | `null` | Arbitrary JSON forwarded to the node's inbox. |
| `timeout_ms` | no | `30000` | Per-call timeout. **Server caps at `300000` (5 min)**; values above the cap are silently clamped. On expiry → 504. |

### Responses

| Status | Body | Meaning |
|---|---|---|
| `200 OK` | `{ "reply_type": "query_result", "payload": <reply json> }` | Handler emitted a matching reply within `timeout_ms`. |
| `400 Bad Request` | (axum default) | Malformed body / missing `type` or `reply_type`. |
| `401 Unauthorized` | `401 unauthorized` | Bad bearer. |
| `403 Forbidden` | `{ "error": "rejected_by_manifest", "reason": "..." }` | `accepts_external_call` did NOT contain a matching `(request_type, reply_type)` pair. |
| `404 Not Found` | `{ "error": "node_not_found" }` | Node id did not resolve. |
| `503 Service Unavailable` | `pending_calls registry full` / `scheduler bridge closed` | `PendingCalls` cap (10 000) reached OR mpsc bridge full / scheduler shut down. |
| `504 Gateway Timeout` | `{ "error": "reply_timeout", "timeout_ms": <ms> }` | `timeout_ms` elapsed before any matching reply arrived. |

### Auto-propagation rules

1. Server mints a UUIDv4 `correlation_id` and registers `(correlation_id → oneshot::Sender<Value>)` in `PendingCalls` (drop-evicting on HTTP-client-disconnect via RAII guard).
2. The drain handler validates `(request_type, reply_type)` against the manifest; mismatch → 403; valid → `SchedulerHandle::send_ingress_with_correlation` injects with `from = "__ingress__"` and the correlation_id.
3. `Scheduler::deliver` consults the manifest's matching `accepts_external_call` entry, captures `(correlation_id, reply_type)` per-handler-invocation. **Save/restore across nested deliveries** so concurrent calls don't cross-contaminate.
4. When the handler emits, `make_emit` checks the per-invocation context: if outgoing `type` matches `reply_type` AND no prior matching emit fired (first-match-only flag), the runtime copies `correlation_id` onto the outgoing `Message` AND fires `TelemetrySink::on_call_reply { correlation_id, payload, from, reply_type }`.
5. `PendingCalls`, installed as a `MultiplexSink` consumer alongside Prometheus + ring buffer + WebSocket, implements `on_call_reply`: looks up `correlation_id`, removes the entry, resolves the oneshot.

**Multi-emit handlers tag exactly the first matching outgoing emit.** A handler that does `emit("log", ...); emit("reply", ...); emit("metric", ...)` tags only the `"reply"`. Subsequent emits with `type = "reply"` in the same invocation do NOT carry the correlation_id (the `tagged` flag flipped after the first match).

### Cluster-wire propagation (WIRE_VERSION 4 + `ingress-call-v1` capability)

`Message.correlation_id` propagates over the cluster wire format at `WIRE_VERSION = 4` (bumped from 3 with the M-Ingress phase 2 ship). The bump is a hard floor (`MIN_SUPPORTED_VERSION = 4`); v3 peers cannot interop with v4 peers, matching M16-Backend Phase 10's `WIRE_VERSION 2 → 3` precedent. Rolling-version negotiation remains M-Prod scope.

Within v4, the `INGRESS_CALL_V1_CAPABILITY = "ingress-call-v1"` flag advertised in `Hello.capabilities` / `ChallengeAck.server_capabilities` gates correlation_id propagation outbound: a sender targeting a peer WITHOUT the capability strips correlation_id (sets it to `None` on `wire::Message`) before encoding, even if the local Message's value is `Some(_)`. Receivers from peers without the capability still parse the field but treat the value as semantically inert (no `PendingCalls` registry to resolve against).

The `grx cluster daemon` always advertises `ingress-call-v1` because the management API call endpoint ships by default; non-call workloads pay no additional cost (correlation_id stays `None` on every emit).

## POST /v1/nodes/:id/messages/bulk — streaming NDJSON inject

Streaming bulk dispatch for ingestion-shaped applications (firehose audit logs, trust-event streams, batch ingest). Per-line manifest gating + per-line idempotency + streaming per-line ack response. The HTTP layer is fire-and-forget per-line — no reply matching.

### Request

```http
POST /v1/nodes/logger.global/messages/bulk HTTP/1.1
Authorization: Bearer <token>
Content-Type: application/x-ndjson
Content-Length: <total bytes>

{"type":"audit","payload":{"actor":"alice","action":"login"},"idempotency_key":"a1"}
{"type":"audit","payload":{"actor":"bob","action":"logout"},"idempotency_key":"a2"}
{"type":"audit","payload":{"actor":"carol","action":"upload"},"idempotency_key":"a3"}
```

**Line shape:** each NDJSON line is a JSON object terminated by `\n`. `\r\n` is also tolerated. Blank lines are silently skipped (don't increment the line counter, don't reach the bridge).

| Field | Required | Notes |
|---|---|---|
| `type` | yes | Message type. Runtime-checked against `manifest.accepts_external` (single-shot allowlist — same gate Phase 1 uses). Bulk does NOT use `accepts_external_call`. |
| `payload` | no (default `null`) | Arbitrary JSON forwarded verbatim. |
| `idempotency_key` | no | Per-line opaque dedup key. Shares the 10-min TTL + 10k-entry-cap `IdempotencyCache` with Phase 1's `Idempotency-Key` header. Per-line because the HTTP header is single-valued and doesn't apply to a multi-line request. |

### Caps

| Constant | Default | Configurable | Effect |
|---|---|---|---|
| Line count | 10 000 lines | Yes — `GRX_INGRESS_BULK_LINE_CAP` env var | Beyond cap → final `{"line": N, "result": "exceeded_line_cap"}` line + stream close. |
| Per-line bytes | 1 MiB (`BULK_MAX_LINE_BYTES`) | No — substrate-level safety | Oversized line emits `{"line": N, "result": "line_too_large"}` and parser resyncs to the next `\n`. |
| Total body bytes | 10 GiB (`BULK_MAX_BODY_BYTES = lines × max-line`) | No (derived) | Pre-flight `Content-Length` cap → 413 before body reaches handler. |

### Response

`200 OK` + `Transfer-Encoding: chunked` + `Content-Type: application/x-ndjson; charset=utf-8`. Body is a stream of per-line response records:

```ndjson
{"line":0,"result":"accepted"}
{"line":1,"result":"accepted"}
{"line":2,"result":"rejected_by_manifest"}
{"line":3,"result":"idempotency_conflict"}
{"line":4,"result":"bad_json"}
```

The 200 status is sent at handler entry (after the pre-flight `Content-Length` check). Even a partial-failure run that hits the cap mid-body returns 200 + the streamed terminator — the per-line response shape is the source-of-truth for client decision-making.

| `result` | Semantics |
|---|---|
| `accepted` | Manifest gate passed; message dispatched via `SchedulerHandle::send_ingress`. |
| `node_not_found` | Target node id did not resolve at dispatch time. |
| `rejected_by_manifest` | `manifest.accepts_external` does not contain this `type`. **Distinct from Phase 1's single-shot path** (which defers manifest gating to delivery + observes via telemetry stream); bulk hoists the gate to drain so streaming clients see the rejection inline. |
| `bad_json` | Line failed JSON parsing. The bridge is NOT invoked. |
| `idempotency_conflict` | `idempotency_key` matched a non-expired entry in the shared `IdempotencyCache`. Bridge NOT invoked. |
| `backpressure_503` | mpsc bridge full at this line. Handler emits this terminator AND closes the response stream. Clients should retry from line N+1 after backoff. |
| `bridge_dropped` | Drain side dropped its `oneshot::Sender` before responding (typically scheduler shutdown). Stream continues for subsequent lines. |
| `exceeded_line_cap` | `GRX_INGRESS_BULK_LINE_CAP` reached. Final terminator line; stream closes. |
| `line_too_large` | Line bytes exceeded `BULK_MAX_LINE_BYTES = 1 MiB`. Handler resyncs to the next `\n` and continues processing subsequent lines. |

### Error responses (status ≠ 200)

| Status | Body | Meaning |
|---|---|---|
| `401 Unauthorized` | `401 unauthorized` | Bad bearer. |
| `413 Payload Too Large` | `{ "error": "body_too_large", "max_bytes": <n> }` | Pre-flight `Content-Length` exceeded `BULK_MAX_BODY_BYTES`. Body never reaches the streaming handler. |
