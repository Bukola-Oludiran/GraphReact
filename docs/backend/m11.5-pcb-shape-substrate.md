## Key reconciliation: §2.4 ID collision

The doc's literal §2.4 rule ("two graph nodes with the same fully-qualified id is a hard parse error") would have broken GraphReact's load-bearing **multi-parent pattern** — the same logical node receiving edges from multiple parents via duplicate-id-with-no-attrs. The TS reference documents this at [`compiler.ts:6`](../../../../../graphreact/src/core/parser/compiler.ts) ("Multi-parent edges (duplicate id = connect to new parent)"), and two of the four canonical example fixtures rely on it ([`counter-network.grx`](../../../../../graphreact/src/examples/counter-network.grx), [`multi-file/main.grx`](../../../../../graphreact/src/examples/multi-file/main.grx)).

Adopted rule:

- **First occurrence** of an id declares the node with attrs + component tag.
- **Subsequent occurrences** MUST have no attributes beyond `id`, AND MUST use the same component tag.
- Any subsequent occurrence carrying attrs (beyond `id`), or using a different component tag, is a hard error citing both source locations.

The PCB cross-file collision case (e.g., `rf.grx` and `mcu.grx` both defining `<Net id="GND" footprint=...>` after unaliased import) is caught because both sides carry attrs. The pure GraphReact multi-parent pattern (id-only re-mention) stays valid.

## Architecture decisions

1. **CSS desugarer in `crate::style` module** — default-on, no Cargo feature flag, but module-isolated so PCB-domain semantics don't bleed into the parser core. Invoked from `build_ir` and tree-sitter `process_graph_node` as a post-parse pass on each `NodeDecl.attrs`; consumes the `style` key.

2. **Splice is an IR-build pass, not a parser pass** — the parser produces a vanilla `NodeDecl { component: "Subsystem", attrs: {ref, id, ...} }` for `<Subsystem>` elements. Splice resolution happens in `ir::process_children` when it encounters `node.component == "Subsystem"`, consulting a `SubgraphLookup` built from `file.subgraphs`.

3. **Cross-file subgraph rollup via `MultiFileResolved::collect_root_subgraphs`** — root-level imports register their subgraphs under alias-qualified keys (`"<alias>:<name>"`). Unaliased imports flatten. Transitive imports (imports-of-imports) are out of scope for v1 — they don't propagate alias context.

4. **`build_ir` signature changed from `fn(&GrxFile) -> GrxIr` to `fn(&GrxFile) -> GrxResult<GrxIr>`** — collision detection + splice errors propagate as `GrxParseError` variants. Existing callers in graphreact-cli updated to `?`-propagate; existing tests updated to `.expect("build_ir ok")`.

5. **Tree-sitter parity for Part 1 (Subgraph + alias)** is structural; for Part 2 (CSS desugaring) it routes through the shared `crate::style::desugar_style` function. **Subsystem splice parity is deferred** — the tree-sitter bridge does not yet run splice resolution. Fixtures with Subsystem references are excluded from cross-backend parity until the bridge is refactored to route through the hand-rolled AST builder (follow-up scope).

6. **`<Subgraph>` and `<Subsystem>` are reserved tag names** added to `lexer::reserved_tags()` so the raw-content lexer trigger doesn't misclassify them as definition blocks (they have no `id` attribute, which is the default trigger).

## Follow-on items shipped same day (2026-05-26)

After the initial milestone landed, PCBPnR session flagged two items from the deferred list as actual blockers for Phase 5-D Part 3. Both shipped immediately:

### #1 — Re-sugaring (numeric → CSS) — SHIPPED

New module [`crate::style::resugar`](../../crates/graphreact-grx-parser/src/style/resugar.rs). Mirror of `desugar` — takes a typed-numeric AttrMap and produces the equivalent `style="…"` CSS body. `pub fn resugar_attrs(tag_name: &str, attrs: &AttrMap) -> Resugared` returns both the CSS string and the non-CSS-eligible `remaining` attrs so callers can render `<Foo id="x" footprint="0402" style="…"/>` directly.

Canonical CSS forms chosen for many-to-one cases:
- `at.rot` → emits `rotate: Ndeg` (not `transform: rotate(Ndeg)` — simpler form).
- Properties emitted in stable canonical order (position-first → layer info → geometry/clip-path → misc) for reproducible `.grx` output.
- All 7 `clip-path` shape variants supported in reverse (`rect`/`round_rect`/`circle`/`ellipse`/`polygon`/`path`/`native`).

20 round-trip tests (per-property + multi-property + idempotency: `desugar(resugar(x)) == x` for the typed-key subset).

### #2 — External `.py` body file loading — SHIPPED

New self-closing definition shape: `<Component src="./body.py" lang="python" />`. The hand-rolled parser populates a new `NodeDefinitionBlock.src: Option<String>` AST field; the multi-file resolver reads the external file relative to the importing `.grx` directory and populates `code`. The tree-sitter grammar gained `_definition_self_close` to recognize the same shape; both backends parse external-body definitions identically.

Resolver paths covered: `resolve_multi_file` (disk IO), `resolve_multi_file_cached`, `resolve_multi_file_cached_treesitter`, and `resolve_multi_file_with` (callback-based for in-memory tests). The PCBPnR session can fuzz/test without touching disk via the callback variant.

Error path: `GrxParseError::DefinitionBodyIo { component, path, source, loc }` — points at the definition's source loc for editor diagnostics.

Mutually-exclusive guard: a definition block with both `src=` AND an inline body is a parse error. A self-closing definition without `src=` is also rejected (would be meaningless — no body anywhere).

7 new tests covering: parse + AST shape, missing-file error, in-memory callback variant, regression on existing inline-body fixtures, conflict detection.

- **Transitive-import alias propagation** — see decision 3 above. Only matters for 3+ level board hierarchies; Phase 5-B `auto_decompose` produces 2-level by construction.
- ~~**`cm` / `inch` / `px` unit support**~~ — **SHIPPED via Cleanup-Pass `m115-css-units` (2026-06-17).** All four CSS-standard length units accepted and canonicalized to mm at parse time (1cm = 10mm, 1in = 25.4mm, 96px = 25.4mm at the CSS reference DPI). Bare numbers without a unit are still rejected to avoid silent unit confusion. Resugar always emits `mm` — internal representation is the canonical form. Implementation in [`crates/graphreact-grx-parser/src/style/units.rs`](../../crates/graphreact-grx-parser/src/style/units.rs).

- **CSS-selector parsing** — separate from CSS property strings; only needed if Phase 5-E's `tool:state:query` accepts CSS selectors as INPUT. Decision pending.
