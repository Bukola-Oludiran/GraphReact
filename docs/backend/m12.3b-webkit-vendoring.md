# M12.3b WebKit vendoring

**Status:** living document. Last updated: 2026-05-02 (M12.3b-phase2 — `xtask webkit-clone` + `xtask webkit-build` orchestration).

## Why vendoring exists

`graphreact-engine-jsc` links against JavaScriptCore. On macOS that's the system framework at `/System/Library/Frameworks/JavaScriptCore.framework` (no vendoring needed; M12.3a + M12.3b-phase1.5). Linux and Windows do **not** ship JSC; we need to vendor WebKit and build `libJavaScriptCore.a` ourselves.

Phase 2 (this slice) ships the **orchestration** — two `xtask` subcommands that clone WebKit at a pinned ref and run the JSCOnly cmake build. It does **not** actually run the multi-hour build; that's phase 3.

## Strategic shape — variant (b)

| Platform | JSC source | drain_microtasks |
|---|---|---|
| darwin-arm64 / darwin-x86_64 | system framework | extern-C symbol shim (M12.3b-phase1.5) |
| linux-x86_64 / linux-arm64 | vendored WebKit (this doc) | C++ shim against vendored headers (M12.3b-phase4) |
| windows-x86_64 | vendored WebKit (this doc) | C++ shim against vendored headers (M12.3b-phase4) |

macOS keeps the system framework even after vendoring lands — the binary is ~25 MB smaller and Apple's release cadence is gentler than upstream WebKit's. See `project_graphreact_m12_3b_phase1_5.md` for the variant-(b) decision rationale.

## What ships in phase 2

Two `xtask` subcommands defined in [`xtask/src/webkit.rs`](../xtask/src/webkit.rs):

### `cargo xtask webkit-clone`

Clones [WebKit/WebKit](https://github.com/WebKit/WebKit) at the pinned ref into `vendor/WebKit/`. If a clone is already present, fetches the ref and checks it out (detached HEAD).

```sh
cargo xtask webkit-clone                              # default ref, shallow
cargo xtask webkit-clone --ref <commit-or-tag>         # override ref
cargo xtask webkit-clone --full-history                 # disable --depth=1
cargo xtask webkit-clone --dry-run                      # print commands, don't execute
GRAPHREACT_WEBKIT_REF=<commit> cargo xtask webkit-clone # env-var override
```

Writes `vendor/WebKit/.graphreact-stamp` recording the actual ref used so future invocations can verify the clone is at the expected version.

### `cargo xtask webkit-build --target <triple>`

Runs `cmake -GNinja` then `ninja jsc` against the cloned source, producing `libJavaScriptCore.a` (or `JavaScriptCore.lib` on Windows) under `target/webkit/<triple>/<mode>/lib/`.

```sh
cargo xtask webkit-build --target linux-x86_64                # release
cargo xtask webkit-build --target linux-arm64 --debug         # debug
cargo xtask webkit-build --target windows-x86_64 --dry-run    # print cmake/ninja, don't run
```

Supported triples:

| Triple | Cargo equivalent | Status |
|---|---|---|
| `darwin-arm64` | `aarch64-apple-darwin` | parity-only (uses system framework in production) |
| `darwin-x86_64` | `x86_64-apple-darwin` | parity-only (uses system framework in production) |
| `linux-x86_64` | `x86_64-unknown-linux-gnu` | the canonical Linux target |
| `linux-arm64` | `aarch64-unknown-linux-gnu` | server / cloud / Apple Silicon Linux VMs |
| `windows-x86_64` | `x86_64-pc-windows-msvc` | Windows server |

## Pinned WebKit ref

Set in [`xtask/src/webkit.rs::WEBKIT_REF_DEFAULT`](../xtask/src/webkit.rs).

**Default**: `main` (placeholder). **Phase 3 kickoff** chooses a specific commit verified to build cleanly across all five target triples and updates the constant.

Override at clone time with `--ref <commit>` (CLI) or `$GRAPHREACT_WEBKIT_REF` (env). The actual resolved ref is written to `vendor/WebKit/.graphreact-stamp` for reproducibility.

## CMake flag matrix

Shared across all targets (mirrors a subset of Bun's [`scripts/build/deps/webkit.ts`](../../bun/scripts/build/deps/webkit.ts) — minus the bun-specific `USE_BUN_JSC_ADDITIONS` / `USE_BUN_EVENT_LOOP` that we don't need):

| Flag | Value | Purpose |
|---|---|---|
| `PORT` | `JSCOnly` | WebKit's "JSC-only, no DOM/HTML/CSS" port. Smallest viable build. |
| `ENABLE_STATIC_JSC` | `ON` | Produce `libJavaScriptCore.a` instead of a shared object. |
| `USE_THIN_ARCHIVES` | `OFF` | Thick archives so the static lib is fully self-contained. |
| `ENABLE_FTL_JIT` | `ON` | Optimising tier; required for production-quality JS performance. |
| `ENABLE_REMOTE_INSPECTOR` | `ON` | Enables CDP-style debugger attach (M16 observer hook). |
| `ENABLE_API_TESTS` | `OFF` | Don't build WebKit's own test suite — ours is the runtime + grx fixtures. |
| `ENABLE_MEDIA_SOURCE` | `OFF` | We're a JS engine, not a browser. |
| `ENABLE_MEDIA_STREAM` | `OFF` | Same. |
| `ENABLE_WEB_RTC` | `OFF` | Same. |
| `CMAKE_EXPORT_COMPILE_COMMANDS` | `ON` | LSP `compile_commands.json` for editor jumping during phase 4 wiring work. |
| `CMAKE_BUILD_TYPE` | `Release` / `Debug` | Per-mode. |

Per-target additions:

| Condition | Flag | Value | Why |
|---|---|---|---|
| target ≠ host (cross-compile) | `CMAKE_SYSTEM_NAME` | `Darwin` / `Linux` / `Windows` | cmake auto-detects on native; cross needs an explicit setting. |
| target ≠ host | `CMAKE_SYSTEM_PROCESSOR` | `x86_64` / `aarch64` | Same. |
| target = `windows-x86_64` | `CMAKE_MSVC_RUNTIME_LIBRARY` | `MultiThreaded` (release) / `MultiThreadedDebug` (debug) | Static CRT — required because `ENABLE_STATIC_JSC=ON` produces a fully-static archive that must link against the same CRT mode as the consumer. |

Phase 3 will likely need to add: cross-compile sysroot pointer (Linux→Linux for older glibc), Windows MSVC version override, ICU build (Windows local mode — Bun runs `build-icu.ps1` before cmake configure). These are the "implementation dependencies" the substrate-not-MVP rule says it's correct to phase-split on.

## Layout

```
graphreactRust/
├── vendor/                 # gitignored
│   ├── .gitignore           # ignores WebKit/
│   └── WebKit/              # ~2-3 GB shallow clone (or full); .graphreact-stamp records ref
├── target/
│   └── webkit/
│       └── <triple>/
│           └── <mode>/
│               ├── build.ninja
│               ├── lib/
│               │   ├── libJavaScriptCore.a    # or JavaScriptCore.lib on windows
│               │   ├── libWTF.a
│               │   └── libbmalloc.a
│               └── compile_commands.json
└── xtask/src/
    ├── main.rs              # subcommand router (existing)
    └── webkit.rs            # M12.3b-phase2 orchestration
```

`target/webkit/` is per-target × per-mode so a single source clone can produce binaries for multiple targets without re-cloning. `rm -rf target/webkit/` is a clean reset that doesn't touch the clone.

## What's NOT in phase 2

- **The actual clone** (10+ minutes, ~2-3 GB) and **build** (multi-hour first run, incremental thereafter). Phase 3 runs these on the appropriate host (probably CI, given the build cost).
- **Cross-compile sysroots / toolchain files**. The flag matrix emits `CMAKE_SYSTEM_NAME` / `CMAKE_SYSTEM_PROCESSOR` for cross targets but doesn't yet supply a sysroot — phase 3 chooses sysroot strategy per target (Docker for Linux, MSVC SDK for Windows, etc.).
- **Wiring vendored libJSC into `graphreact-engine-jsc`'s `build.rs`**. Phase 4 swaps the `cargo:rustc-link-lib=framework=JavaScriptCore` (currently macOS-only) for a vendored-static-lib link on non-macOS targets, and rewrites `drain_shim.cpp` to use the vendored WebKit headers instead of the forward-declared `JSC::VM` class.
- **CI matrix.** Phase 5.
